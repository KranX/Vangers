# Пакеты локализации

Этап 3 [плана локализации](text-localization-roadmap.md). Локаль — строковый ID
пакета, а не новый элемент `Language` для каждого языка. В этом этапе вынесены
существующие RU/EN строки интерфейса и выбор ресурсов; перевод и рендеринг
не переписываются.

## Выбор языка

Запускать игру, как прежде, из каталога её данных:

```sh
/path/to/vangers --locale ru
/path/to/vangers --locale en
```

В корне `settings.toml` можно сохранить `locale = "ru"`. Без этого поля
используется `en`. `--locale` перекрывает настройку только на данный запуск;
не переписывает сохранённый выбор. Старый `-russian` и явный `-english` работают
как псевдонимы; последний селектор командной строки имеет приоритет.
Смена языка требует перезапуска: UI заимствует строки каталога на время жизни
интерфейса. Горячая замена каталога с живыми указателями не поддерживается.

ID содержит 1–48 ASCII-символов `a-z`, `0-9`, `-`, без дефиса по краям:
например, `en`, `ru`, `pt-br`. Регистр не нормализуется молча. `../ru`, пути,
пустые и прописные ID отклоняются с диагностикой.

## Файлы пакета

```text
locales/
  en/manifest.toml
  en/strings.toml
  ru/manifest.toml
  ru/strings.toml
```

Сначала проверяется `locales` в рабочем каталоге игры; при отсутствии этого
каталога используется `locales` у приложения (`SDL_GetBasePath`, для macOS `.app`
это `Contents/Resources`). Сборка копирует пакеты рядом с бинарником; CI-архивы
Linux/Windows, macOS bundle и Flatpak доставляют их в соответствующее место.
Покупные игровые данные менять ради базовых каталогов не требуется.
`VANGERS_LOCALES` позволяет явно заменить корень для тестов/модов. Существующий
локальный или явно заданный повреждённый каталог не маскируется установленным. Пути ресурсов
в манифесте всё равно относительны **каталогу данных игры**, не каталогу пакета.
Английский пакет обязателен: он задаёт набор ключей и базовые ресурсы.

В каждом штатном каталоге **634 строки**: 394 подписи из прежних таблиц UI,
219 имён/подсказок/комментариев/шаблонов предметов, 19 названий миров/циклов
и две служебные строки. Это не весь текст игры: большие диалоги и история
остаются отдельными текстовыми ресурсами.

Минимальный дополнительный пакет может содержать:

```toml
# locales/zz-test/manifest.toml
legacy_language = "en"

[resources]
"history.prelude" = "locales/zz-test/prelude.txt"
```

```toml
# locales/zz-test/strings.toml
[strings]
"menu.iSTR_NEW_GAME" = "NEW VOYAGE"
"actint.aciSTR_PRICE" = "Price: "
```

Остальные строки и роли ресурсов берутся из `en`, с диагностикой пропусков.
Сценарии, геометрия, действия кнопок и игровые ID копировать не нужно.
`legacy_language` — только адаптер ещё старых RU/EN путей, а не ID перевода.
Без него используется английское legacy-представление. Можно заимствовать
профиль `ru`, явно указав соответствующие существующие UI-ресурсы, как
в штатном русском манифесте. История выбирает документы по ID реально
загруженного ресурса, а не по значению `Language`.

### Строки и шаблоны

Все значения `[strings]` — UTF-8. Ключи стабильны, длиной 1–128 символов
`A-Z a-z 0-9 . _ -`; менять их при редактуре перевода нельзя. В TOML ключи
с точками нужно заключать в кавычки. Пустая строка — явное значение, не пропуск.
Встроенный NUL, неверный UTF-8, нестроковое значение и неизвестный ключ — ошибки.

Динамические подписи предметов используют один `%d` или `%s`; `%%` выводит `%`.
Тип и количество аргументов перевода должны соответствовать английскому
шаблону. Перевод не передаётся в `printf`: специальные спецификаторы,
ширина/точность и лишние аргументы отклоняются. Формирование идёт в `std::string`,
не в фиксированный буфер.

### Ресурсы и кодировки

Манифест выбирает 28 ролей: архив Diagen, исходный/бинарный iscreen,
два разрешения actint (исходники и бинарники), ACS (исходник и бинарник),
карту главного меню, три исторических текста, 13 страниц титров и два
финальных изображения. Полный перечень — в `data/locales/en/manifest.toml`.

Файловые пути не могут быть абсолютными, содержать `..`, `:` или обратную
косую черту. Это защита от ошибочного пути пакета, не песочница для симлинков.
Для текстовых файлов новая переопределённая роль по умолчанию означает UTF-8.
Только старые CP866-файлы требуют явного указания:

```toml
[resources]
"history.prelude" = "resource/iscreen/text/rus/prehist.txt"

[encodings]
"history.prelude" = "cp866"
```

Разрешены `utf8` и `cp866`. Кодировка английского ресурса сохраняется при fallback;
она не наследуется случайно при подмене роли новым UTF-8-файлом. Для бинарных
SCB/DU и изображений это поле не используется. Diagen имеет собственный
явный контракт UTF-8/старых архивов из предыдущего этапа.

### Что считается пропуском

- Нет манифеста выбранного пакета — используется `en` целиком.
- Нет ключа строки или роли ресурса в выбранном пакете — используется
  соответствующий ключ `en` и выдаётся диагностика при загрузке, не каждый кадр.
- Указанный пакет повреждён, нет его `strings.toml`, неверен тип/ключ/кодировка
  либо явно выбранный файл не читается — это ошибка, а не скрытый fallback.
- Неполный **исходный** Diagen-перевод получает отсутствующие `.query`/`.text`
  файлы из `data/en`, с диагностикой. Содержимое частично написанного файла
  не объединяется с английским построчно или по репликам автоматически.

Заведомые пропуски EN, требующие нового перевода, перечислены в
[`diagen-english-audit.md`](diagen-english-audit.md). Новых переводов здесь нет.
Каждый комментарий предмета — целая единица перевода/fallback, а не набор ключей
по старым номерам строк. Оба UI-профиля читают один и тот же полный комментарий,
даже если старый EN имел одну строку, а RU — две. Намеренные исходные разрывы
сохранены внутри UTF-8-значения; существующая измеряемая вёрстка панели разбивает
его на отображаемые строки. Правка перевода не требует менять `comments N` или
SCB. Однострочные английские фразы не дополнены новым переводом или пустыми
фиктивными комментариями.

## Контракт исходников и сборка ресурсов

На границе **отображаемого** поля iscreen/actint/ACS строка `@l10n:key`
разрешается через каталог. Обычный литерал остаётся совместимым. Префикс
распознаётся только в начале всей строки, не как подстановка внутри текста.
Имя текстового файла `@resource:role` в iscreen разрешается через манифест
вместе с его кодировкой: история, `text` и `s_text` (включая титры).

Имена объектов/сценариев, ID предметов и квестов, UVS lookup-теги, первая часть
имени эскейва и имя мира на карте **не переводятся**. Отображаемая вторая часть
имени эскейва, `world.<lookup-id>` и `cycle.<lookup-id>.<index>` — отдельные
подписи. Неизвестные модовые миры сохраняют старый ресурсный fallback.

Исходники UI теперь содержат ключи. Для доставки новых переводов нужно
**перекомпилировать все восемь SCB**, а не запускать игру с прежними буквальными
подписями в приватном комплекте данных. Старые SCB по-прежнему читаются, но
их литералы сами собой переводимыми не становятся. Изменение только TOML
после перехода на keyed SCB перекомпиляции интерфейса уже не требует.

При наличии полного соответствующего комплекта данных:

```sh
cmake --build /path/to/build --target vangers_iscreen_compiler
cmake --build /path/to/build --target compile_interface_scripts
```

Историческое имя `compile_iscreen_scripts` также работает и теперь собирает
все восемь файлов. Этот target записывает бинарники в `data/resource` исходного
дерева, как прежний target. Для изолированной проверки запускать компилятор
из **копии** полного каталога данных:

```sh
/path/to/build/src/vangers_iscreen_compiler --compile-iscreen iscreen/oftr.scr resource/iscreen/oftr.scb
/path/to/build/src/vangers_iscreen_compiler --compile-actint actint/aci_low.scr resource/actint/aci_low.scb
/path/to/build/src/vangers_iscreen_compiler --compile-acs actint/acs_low.scr resource/actint/acs_low.scb
```

Аналогично собрать `oftr2`, `aci_low2`, `aci_hi`, `aci_hi2`, `acs_low2`.
Компилятор использует настоящие парсеры; некоторые ресурсы шрифтов/шторок
требуются и при компиляции. Результат заменяется только после успешной записи
временного SCB. Пакеты `data/locales` нужно доставлять вместе с этими данными.

Авторинг Diagen: общий `data/data/*.dil` и `room.lst`, переводы — в
`data/data/<locale-id>/*.query` и `*.text`. Инструмент
`diagen_source_test pack <locale-id>` (из отдельного staging-каталога с `data/`)
собирает `diagen_new.text`; положить его по роли `diagen` в манифесте.
Директория третьей локали не требует нового условия C++ или копии сценария.
Плоские исторические исходники остаются совместимыми.

## Проверки и границы этапа

Тесты проверяют сохранность исходных RU/EN формулировок контрольными суммами,
Unicode без потери при хранении, fallback/диагностику, шаблоны, CLI, settings,
реальные source/SCB парсеры всех трёх UI, все 73 непустых комментария обоих
профилей в RU/EN, поиск каталогов у перемещённого приложения без дерева исходников,
контекстные ошибки `@resource` в `text_object`/`text`/`s_text`, переходы истории независимо от
`Language`, подписи назначений клавиш и сборку неполной третьей локали Diagen.
Используются прежние тесты ID диалогов, сохранений, вёрстки и рельефа.

Этот этап не меняет контур/материал букв, формат квестов, сетевой протокол
или прохождение. Длинные тела текста используют уже принятую автоматическую
вёрстку; однострочные кнопки не становятся автоматически многострочными.
AVI-описания предметов — этап 4; покрытие новых алфавитов, shaping/RTL и CJK
переносы — этап 5; остаточные UVS/компас/чат/сетевые CP866-границы — этап 6.
Успешный тест хранения иероглифов не означает, что нынешние три TTF их содержат.
