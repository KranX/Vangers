# Три контурных шрифта Vangers

**6 октября 2026 года.** По отдельному разрешению владельца сделаны три
статических TTF для разных вариантов оформления. Это проверенные
экспериментальные образцы версии 0.10, ещё не подключённые к игре.

| Файл | Исходник и назначение | Нативная ячейка |
| --- | --- | --- |
| [Vangers Menu](VangersMenu-Regular.ttf) | `hfont01.fnh`, декоративные надписи главного меню | 45×50 |
| [Vangers Display](VangersDisplay-Regular.ttf) | `hfont00.fnh`, заголовки настроек и другие интерфейсные надписи | 26×50 |
| [Vangers Text](VangersText-Regular.ttf) | `cfont00.bml`, мелкий текст и диалоги; подробности формы из `cfont03.bml` | 10×18 |

**Исправление прежнего описания:** `hfont00` — не шрифт крупных пунктов главного
меню. `MAIN_FNT=1` в `data/iscreen/scripts/mainmenu.scr:137`, и объект New Game
использует именно его. Menu имеет самостоятельный рисунок; Display и Text
близки, но различаются пропорциями и посадкой. Три файла не означают, что
полностью покрыты все ACS, служебные шрифты и размерные разновидности игры.

## Алфавиты и новые рисунки Menu

Каждый файл содержит `A–Z`, `a–z`, `А–Я`, `а–я`, `Ёё`, цифры,
ASCII-пунктуацию, пробел, NBSP и игровой знак в `U+E000`:
**163 Unicode-позиции, 162 глифа с `.notdef`**.

У Menu только **58 видимых букв** восстановлены из `hfont01`: A–Z и А–Я.
Остальные **102 видимых символа — новые производные рисунки**, а не найденные
в оригинале буквы. Это строчные, Ёё, цифры и пунктуация. Строчные имеют
собственные глифы, а не Unicode-подстановку прописных. Частично переиспользованы
скелеты исходных прописных и орнаментальный штрих `I`; остальные формы заданы
редактируемыми кривыми в [menu_extensions.py](../menu_extensions.py).
Игровой знак бибов перенесён из `hfont00`. Происхождение записано **для каждого
глифа** в [метаданных Menu](VangersMenu-Regular.json); в
[атласе](menu-proof/atlas.png) новые символы помечены `NEW`.

Это предложенное продолжение декоративной гарнитуры: у отсутствовавших знаков
нет исторического эталона, позволяющего подтвердить точность восстановления.
Системные шрифты для игровых глифов не использованы.

## Посадка и интервалы

У Text сохранена **исходная фиксированная неровность букв**. В старом
`aPutStr32` все символы получают одинаковый Y; различие находится в рисунке
глифа, не в случайном смещении при выводе. Новые TTF тоже статические.
Display/Text получают только малые авторские поправки контура по реальному
FreeType-рендеру, максимум 0.25 исходного пикселя на ось; выравнивания всех букв
по единому нижнему краю нет.

В advance уже включены **5 исходных пикселей** для Menu/Display и **1** для
Text. Пять — значение `I_DEFAULT_SPACE`, используемое выбранными iscreen
надписями, а не универсальный интервал всех экранов. Старая Display Study 07
содержала 2 пикселя; это важное отличие новой роли. При интеграции нельзя
повторно добавлять тот же tracking из старого вызова.

TTF масштабируемые, но Text при 14 ppem **не объявляется точной заменой
отдельного `cfont01` 7×14**. Остальные размерные варианты требуют своей сверки.

## Визуальные проходы

Для Display/Text сохранены прежние семь проходов в `../iterations/`.
Дополнительный Text 08 с подгонкой только центров массы отклонён: он ухудшал
пиксельное совпадение. Text 09 и итоговые роли 10 подбирают маленькие смещения
по ошибке реального растеризатора, не по одной геометрической характеристике.

Menu прошёл **шесть последовательных просмотров**. Для каждого сохранены TTF,
настройки, игровые строки, полный атлас, увеличенный образец и `review.json`.

1. [Высота как покрытие](../menu-iterations/01/proof/outline.png) — отклонено:
   рельефная яркость превращалась в дырки и уничтожала верх орнамента.
2. [Силуэт](../menu-iterations/02/proof/outline.png) — восстановлены целые штрихи,
   но при увеличении сохранились растровые ступеньки.
3. [Сглаженные контуры](../menu-iterations/03/proof/outline.png) — убраны крупные
   ступеньки, сбалансирована толщина строчных.
4. [Цифры и строчные](../menu-iterations/04/proof/outline.png) — усилены цифры,
   уточнён орнамент единицы, сглажены производные кириллические строчные.
5. [Уточнение кривых](../menu-iterations/05/proof/outline.png) — сохранены мелкие
   выступы. Техническая проверка обнаружила неверный порядок вычисления LSB.
6. [Исправление метрик](menu-proof/game-text.png) — LSB вычисляется после
   границ `glyf`; повторно просмотрены игровые надписи и полный атлас.

Итоговый Menu побайтово совпадает с `menu-iterations/06/font.ttf`.
Menu 01–05 не брать для интеграции. Замороженные неудачные проходы не удалены.

## Сравнение на тексте игры

[Menu](menu-proof/game-text.png), [Display](display-proof/game-text.png),
[Text](text-proof/game-text.png) сравнивают **реальный TTF через FreeType**
с исходными полями на одинаковых строках и нативных размерах. Просмотрены
также [Menu](menu-proof/atlas.png), [Display](display-proof/atlas.png) и
[Text](text-proof/atlas.png) целиком, включая цифры, знаки и Ёё.

Корпус содержит **18 настоящих RU/EN-строк**: меню и заголовки из
`data/iscreen/scripts/strings.inc` (CP866), четыре полных реплики из
`data/data/Podish.text:30–33` (CP1251). Например: «НОВАЯ ИГРА»,
«Настройка графики», «Очнулся, жалкий?», «Вот так бывает…»,
«Welcome back, poor pilgarlic!». Пути, строки, исходные хеши и полные тексты
сохранены в `*-proof/game-text.json`. Смешанное `бррpp` в русской реплике
содержится в оригинале, это не ошибка новой Unicode-таблицы.

[Три фрагмента настоящих скриншотов](game-checks/game-crops.png) проверены
независимо: исходная ненулевая маска `cfont00` совпала с пикселями каждого
фрагмента **без единого отличия**. Это подтверждает источник и его посадку,
**не** побайтовую идентичность TTF растру. Нижние строки сравнения — офлайн
FreeType с палитрой, извлечённой из этих фрагментов, не снимки игры с TTF.

Для Menu эталон контура — положительный силуэт `height > 128` с сохранением
исходных advances; слабые отрицательные значения 127 учитываются при bearings,
но не превращаются в заливку. Для Display/Text используются нормализованные
поля высоты/палитрового диапазона. Это **разные прокси, не физическое alpha**.
Из контурного TTF нельзя восстановить исходную фактуру высот и освещение.

| Сравнение на нативном размере | Видимых исходных глифов | IoU масок ≥0.5 | Средняя MAE поля |
| --- | ---: | ---: | ---: |
| Menu, силуэт, 50 ppem | 58 | 0.9894 | 0.0417 |
| Display, высота, 50 ppem | 160 | 0.9767 | 0.0841 |
| Text, диапазон, 18 ppem | 160 | 0.9289 | 0.0533 |

Это не проценты художественного качества. Новые 102 символа Menu не участвуют
в «совпадении с оригиналом». Значения между разными типами эталона напрямую
не сопоставляются. Сохранение игрового рельефа — отдельная будущая работа.

## Перепроверка

[Машинный отчёт](validation.json), [проверяющий код](../validate_roles.py):

- три читаемых TrueType-файла с контурами, без bitmap/SVG/variable-таблиц;
- полное заявленное покрытие, непустые глифы, правильные LSB, метрики и winding;
- **2898 проверок растеризации**: 161 символ × 6 размеров × 3 файла;
- нативные advances исходных символов точны; ширины и переносы всех 18 игровых
  фраз совпали при одинаковом проверочном переносе по словам;
- сохранён порядок нижних точек `e < c < k` из исходного мелкого шрифта;
- повторные рендеры детерминированы; **повторная сборка всех трёх побайтово
  идентична** итоговым файлам;
- Fontconfig распознаёт все три как масштабируемые контурные шрифты;
- [браузерная проверка](browser-validation.json): все три TTF загружены,
  образцы просмотрены при ширине 728 и 360 px, переключение сравнений работает.

Проверочный перенос не запускает все алгоритмы раскладки старой игры.
Отсутствие пустых глифов на 14 ppem не доказывает читаемость Menu в таком размере.

## Воспроизведение

Из корня репозитория, с зависимостями `../requirements.txt`, Potrace 1.16
и Fontconfig. Указать **новый** внешний scratch-каталог, не `data/`.

```bash
PY=/path/to/font-lab-venv/bin/python
LAB=docs/text-rendering/font-lab
OUT=/path/to/new-role-font-work

"$PY" "$LAB/build_menu.py" --config "$LAB/roles-v10/menu.json" \
  --output "$OUT/VangersMenu-Regular.ttf" --scratch "$OUT/menu-work"
for role in display text; do
  "$PY" "$LAB/build_roles.py" --config "$LAB/roles-v10/$role.json" \
    --output "$OUT/$role.ttf" --scratch "$OUT/$role-work"
done
"$PY" "$LAB/validate_roles.py" --scratch "$OUT/validation"
"$PY" "$LAB/game_checks.py" --font "$LAB/roles-v10/VangersText-Regular.ttf" \
  --output "$OUT/game-checks"
```

Для листа сверки: `role_proof.py --role menu|display|text --font FONT.ttf
--config CONFIG.json --output NEW_DIR`. `preview_roles.py` готовит браузерный
образец из тех же TTF. Записанный внешний рабочий каталог:
`/home/stalkerg/projects/vangers-font-baseline/2026-10-06-role-fonts`.

## Границы результата

- Код игры, исходные ресурсы, настройки и эталоны этапа 0 не изменены.
- После просмотра владелец одобрил результат **на текущем экспериментальном
  этапе** и отдельно разрешил commit/push рабочей ветки. Это не разрешение
  на подключение нового рендера и не объявление production-ready.
- Нет hinting, кернинга, лигатур, расширенной латиницы, нерусской кириллицы,
  CJK и исправления старого ввода/кодировок. Немецкий ещё не поддержан этим набором.
- `$` намеренно остаётся игровым знаком бибов, не долларом; есть alias `U+E000`.
- Это производные от игровых ресурсов. GPL кода не выдаёт новую лицензию на
  рисунок букв; разрешение на самостоятельное распространение не заявляется.
- Текущие образцы положительно оценены владельцем. Результат будущего игрового
  рендера потребует отдельной проверки; техническое PASS её не заменяет.
